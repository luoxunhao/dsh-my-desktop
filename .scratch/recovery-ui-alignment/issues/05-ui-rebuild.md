# 05 — 恢复页 UI 重建

**What to build:** 按参考实现的结构重建恢复页——原因卡片 + 标签页 + 底部操作栏 +
各功能面板。

**Blocked by:** 02, 04, 07, 08, 09

**Status:** ready-for-agent

## 结构（对齐参考实现的 `recovery/App.tsx`）

```
[原因卡片]          为什么进了恢复模式 / 失败的插件 / 当前 profile 与目录 / 错误详情
[标签页]
  快速恢复          汇总所有可用手段 + 各自适用场景
  插件              清单（核心/profile/外部）+ 禁用态 + 卸载（两阶段确认）
  回滚              checkpoint 槽位（时间/版本/文件数/大小）+ 差异检查 + 回滚
  Profile           列表 + 当前标记 + 切换并重启
  诊断              启动日志 + 导出
  数据              当前目录 / 来源三态 / 切换 / 恢复默认 / 打开配置文件
  重置              出厂重置（预览 → 执行，明确告知不可逆）
[底部操作栏]        重启 / 退出（忙碌时禁用并显示进度）
```

## 数据通道

**保留我们的 IPC，不照搬参考的 scheme + 整页跳转。**

参考实现把状态 base64 塞进 URL query、每次操作 `window.location.assign(href(...))`
整页跳转；我们已经是 IPC（`dshRecovery.*`），对 React 更合适：状态可直接调用、
无需整页刷新。**这是有意的差异**：视觉与结构对齐，数据通道用我们的。

## 验收

- [ ] 六个面板均可渲染，数据来自真实 IPC
- [ ] 破坏性操作走两阶段确认（预览里能看到影响面：槽位/时间/将改动的文件）
- [ ] 三个新能力（数据目录 / 出厂重置 / 打开配置文件）均有对应面板并接通真实后端
- [ ] 忙碌时界面禁用并显示进度
- [ ] 失败时显示原因而非静默失败
- [ ] 浅色/深色均正常；窄窗口可用
- [ ] 截图与参考对比（**逐像素对比需用户提供参考截图**——无法渲染参考的 React 产物）
