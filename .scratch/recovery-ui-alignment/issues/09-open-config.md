# 09 — 打开配置文件与目录

**What to build:** 用系统默认程序打开配置文件，以及在文件管理器里打开目录。

**Blocked by:** 无（只依赖现有的 profile/数据目录解析）

**Status:** ready-for-agent

## 为什么放在恢复页里

用户要改 `settings.yaml` / `cordis.patch.yml` 时，不该被要求自己去翻文件系统找路径——
尤其是在应用起不来、路径可能不寻常（数据目录被改过）的时候。

**在恢复页里造一个编辑器是错的方向**（要处理语法高亮、编码、并发写、崩溃恢复），
用系统默认程序打开才是对的做法。参考实现就是这么做的。

## 交付物（四个入口）

- [ ] 数据目录下的 `settings.yaml`
- [ ] 当前 profile 下的 `cordis.patch.yml`
- [ ] 当前 profile 下的 `package.json`（插件清单）
- [ ] 在文件管理器里**打开 profile 目录本身**

## 必须守住的约束

- [ ] 用 `shell.openPath`，**失败时返回明确原因**而不是静默失败
      （`openPath` 成功时返回空字符串、失败时返回错误描述——必须检查返回值）
- [ ] **文件不存在时给明确提示**，让用户知道是文件没了而不是按钮坏了
- [ ] 路径必须来自**当前已解析的数据目录/profile**，不得由页面传入任意路径
      （否则会变成"网页可以让主进程打开任意文件"）
- [ ] 不依赖运行中的 Host（阶段 5 性质）

## 验收

- [ ] 能打开上述四个入口
- [ ] 文件不存在时返回可读错误而非静默成功
- [ ] **页面无法指定任意路径**（只接受枚举的入口名）——这一条要有测试
- [ ] 全量测试基线不变（406 / 400 / 5）

## 不做

- 不在页面内实现编辑器
- 不做文件内容读写（只打开）
