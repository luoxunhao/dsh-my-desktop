# 阶段 6 追加范围 — 数据目录管理 / 出厂重置 / 打开配置文件

> 用户要求：这三块**要做**（含后端）。本文档先记录调研结论与实施设计。

## 一、为什么不能再推迟

这三块在参考实现里**不是装饰**，而是恢复页的核心自救手段：

- **数据目录管理**：用户的数据目录（我们的 `DSH_HOME`，即 `~/.dsh`）如果被放在一个
  出错的位置（比如指向了一个损坏的磁盘），应用永远起不来。恢复页必须能**改掉这个位置**。
- **出厂重置**：配置损坏到无法逐个修复时的最后手段——清空数据目录重新开始。
- **打开配置文件**：让用户**直接用系统编辑器**改 `settings.yaml` / `cordis.patch.yml`，
  而不是在恢复页里造一个编辑器。

| 模块 | 行数 | 职责 |
|---|---|---|

| `desktop-factory-reset.ts` | **105** | 出厂重置的**安全检查**（拒绝重置文件系统根、拒绝包含受保护路径的目录） |

**合计后端约 700+ 行**，还要接 UI。

## 三、我们与参考实现的根本差异（必须先解决）

| 概念 | dsh-desktop | 我们 |
|---|---|---|
| 数据目录 | **可配置**，有状态文件记录用户选择 | **写死** `DSH_HOME ?? ~/.dsh` |
| 来源优先级 | `default` / `environment` / `desktop` 三态 | 只有环境变量 + 默认值 |
| 操作锁 | 有（防并发改目录） | 无 |
| 出厂重置 | 有（含安全检查） | 无 |

实测确认我们**没有**任何 `dataDirectory` 概念：

```
profiles.ts:256  const home = options.home ?? process.env.DSH_HOME ?? join(homedir(), '.dsh')
```

**所以"数据目录管理"对我们不是"暴露已有能力"，而是从零建立一套概念**：
状态文件格式、来源判定、切换流程、以及**切换后如何让下次启动生效**。

## 四、设计

### 4.1 数据目录状态（新增）

状态文件记录用户选择的数据目录，与 `profile-registry.json` 同层（都在 userData）：

```
{ version: 1, directory: "<绝对路径>" }     // 缺省时表示"用默认"
```

**解析优先级**（对齐参考实现的三态）：

1. `environment` —— `DSH_HOME` 显式设置时，它优先且**只读**（用户用环境变量接管了）
2. `desktop` —— 状态文件里用户选过的目录
3. `default` —— `~/.dsh`

**为什么环境变量优先级最高**：用户显式设了 `DSH_HOME`，就该尊重它；
否则恢复页里改一次目录会让人以为环境变量失效了。

### 4.2 切换流程（危险，必须守约束）

切换数据目录 = 改一个"下次启动去哪儿找数据"的记录。约束：

- [ ] 目标必须是**绝对路径**，且**必须存在且是真实目录**（拒绝符号链接——
      与阶段 2/3 一致的安全边界）
- [ ] **不迁移数据**。参考实现也不迁移：只改指向。页面上必须说清
      "数据不会自动搬过去"
- [ ] **不立即生效**：写完状态后需要重启（与 profile 切换同构）
- [ ] **拒绝危险目标**：文件系统根、当前 userData、以及任何**包含受保护路径**的目录
      （对齐 `assertDesktopFactoryResetTarget` 的 `contains` 检查思路）
- [ ] 操作期间加锁，防并发/连点

### 4.3 出厂重置（最危险的操作）

参考实现的安全检查值得**逐条对齐**：

- [ ] **拒绝重置文件系统根**（`parse(target).root` 比较）
- [ ] **目标必须是真实目录**（非符号链接）
- [ ] **拒绝重置包含受保护路径的目录**（例如 userData 在数据目录里面时，
      重置会把应用自己的状态也删掉）
- [ ] 确认流程要**明确告知不可逆**，且这是两阶段确认最该用的场景

### 4.4 打开配置文件

最简单的一块——用系统默认程序打开：

- [ ] `settings.yaml`（数据目录下）
- [ ] `cordis.patch.yml`（当前 profile 下）
- [ ] `package.json`（当前 profile 的清单）
- [ ] 打开 profile 目录本身

用 `shell.openPath`；文件不存在时**给明确提示**而不是静默失败。

### 4.5 与恢复模式的既有约束

- **不依赖运行中的 Host**（阶段 5 核心性质）：这三块的 IPC 都必须与 DSH server 无关
- **恢复模式下不启动 Host** 不得回退

## 六、风险（必须正视）

1. **这是三个新子系统，不是 UI 工作**。参考实现相关后端 700+ 行，
   加上 UI 与测试，规模可能超过阶段 6 原有的全部内容。
2. **出厂重置是破坏性最强、最难挽回的操作**。必须先把安全检查与确认流程做对，
   再谈 UI。**引号对齐参考实现的每一条拒绝条件**。
3. **数据目录切换会改变 `DSH_HOME`**，而我们大量代码（profile、checkpoint、
   safe-mode）都建立在它之上。必须确认切换后**所有下游路径都跟着变**，
   否则会出现"改了目录但仍在读旧目录"的静默失效——这与阶段 3 的路径映射陷阱同类。
4. **不能迁移数据**这一限制必须在 UI 上说清，否则用户会以为数据跟着走。
