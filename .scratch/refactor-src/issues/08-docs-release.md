# 08 — 文档收尾 + 发版 0.1.4

**What to build:** 把重构后的**实际**结构记录成项目文档，并发布一个带明确回退点的版本。

**为什么文档放最后**：它要记录实际发生的结构，而不是计划中的结构。07 允许拆不干净，所以最终
形态只有做完才知道。

**为什么单独一个 ticket**：与 07 分开，使得无论 IPC 拆到什么程度，文档与发版都能独立完成——
避免出现"拆到一半要不要发版"的尴尬。

**Blocked by:** 07 — 拆 installShellIpc

**Status:** ready-for-agent

- [ ] 写 `CONTEXT.md`（仓库根）：记录本次澄清的领域术语，例如可变状态 store、晚绑定、
      启动服务、窗口注册表、组合根。术语表只放本项目特有的概念，不放通用编程概念
- [ ] 写 1~2 条 ADR（`adr/`，**不是** `docs/adr/`——该目录被 gitignore）：
      至少包含「为何用依赖注入而非事件总线」这条决策及其权衡
- [ ] 更新 `AGENTS.md` 的「关键文件」章节为新路径
- [ ] 更新 `AGENTS.md` 的测试基线数字（若已变化）
- [ ] 版本升到 0.1.4（启动器与随包插件同步）
- [ ] `dist-local` 出包成功，产物文件名带 0.1.4
- [ ] 提交并打 annotated tag `v0.1.4`
- [ ] 确认最终验收：`src/` 无平铺文件、主入口 < 300 行、跨层依赖单向、测试基线不退化

**备注**：若 07 未能拆干净，在 ADR 或 `AGENTS.md` 中记录"主入口仍承载部分 IPC 注册"这一现状
及原因，避免后续 agent 误以为它是遗漏。
